# 验证与故障排查

## 证据分层

1. **自动化测试**：GitHub Actions 编译与合成 UIKit 场景，验证实现的可重复行为。
2. **运行时诊断**：用户设备上的调用、缓存、恢复及服务端回执计数。
3. **用户确认**：真实 QQ 中看到的消息、交互及好友端结果。

三类证据互相补充，不能互相代替。每次发布的构建结果应以对应 Actions 运行状态为准。

## 如何读诊断

- `hook_results` 中的 0 表示安装成功，调用数看 `hook_calls` 等字段。
- `intercepted_events` 为 0 可能只是本次没有新撤回，不能单独判断失效。
- `history_records_restored` 是恢复次数，不是去重消息数。
- `images_saved` 是本次新增数；`saved_images_current_account` 是现有副本数。前者为 0 不代表缓存丢失。
- `content_cache_hits` / `content_state_checks` 反映布局内容查询复用；不是帧率。
- `coalesced_layout_callbacks` 记录合并的布局请求；`hierarchy_scans` 记录必要的视图搜索。
- `height_refreshes`、`footer_space_unavailable` 用于排查行高调整与遮挡。
- 设备名回执需结合 HTTP 状态、`outer_code`、`inner_code` 和两个 `has_*_code` 标记。成功回执不等于自动确认好友显示。
- 未证实含义的服务端错误码不擅自解释，例如早期 -5。

## 回归检查建议

升级后检查：滚动长聊天、图片与文字混排、停在最新消息接收新消息、向上阅读历史、开启键盘、退出重进聊天、切换深色模式和较大字体。

对闪照验证：打开新图片、重复回看、关闭开关、清理当前账号副本。不要用已经销毁且从未保存的图片判断保存功能是否正常。

如果仍卡顿，请说明具体触发动作与是否持续。当前没有真机帧时采样，不能仅凭 Hook 次数声称达到某个帧率。

## CI 与产物

CI 覆盖版本/ABI 拒绝、转发行为、撤回更新顺序、跨进程持久化、消息身份隔离、UIKit 标识几何、复用、底部跟随、历史滚动位置、闪照回看、设置入口及机型请求适配。

产物只包含插件与合成测试证据，不含第三方 IPA 或用户聊天数据。安装包须重新签名。
