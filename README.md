# QQ 名片赞领取辅助工具

版本 **1.1.0** · 独立分支 `codex/qq-card-claim-once`

通过 GitHub Actions 检查第三方站点的免费名片赞商品，并区分价格预览、订单受理和实际到账。该分支独立于 `main` 的 QQ iOS 插件；升级不会改变插件功能。

## 当前状态

- 2026-11-16：一次免费 100 赞订单被站点受理，用户截图确认总数由 28 增至 128。
- 同日再次检查：价格预览通过，但下单被拒绝，提示商品可购买或领取名额不足。
- 无法仅凭该回执判断限制作用于 QQ 号、IP、会话、库存或时间窗口。
- **当前工作流不提交订单，也没有定时领取。** Push 只运行离线测试。

## 状态含义

| 状态 | 含义与后续操作 |
| --- | --- |
| `product_visible` | 页面存在目标商品和免费按钮，未校验账号资格 |
| `free_preview_available` | 价格预览明确免费，不代表下单有额度 |
| `quota_exhausted` | 站点提示额度不足或 HTTP 429；停止，不自动重试 |
| `already_claimed` | 站点提示已领取；不重复提交 |
| `login_required` / `verification_required` | 需要人工处理登录或验证；停止 |
| `free_price_not_confirmed` | 未明确确认零元，包括缺字段或价格变化；不下单 |
| `preview_timeout_no_order` | 预览超时，未下单 |
| `order_accepted` | 站点受理订单，**不是 QQ 实际到账证明** |
| `submission_unknown_do_not_retry` | 请求已发出但回执不明确；先核对订单，禁止盲目重试 |
| `provider_rejected` / `http_error` | 站点拒绝或网络服务异常 |

`arrival_verified` 始终由自动化记录为 false：脚本无法访问用户 QQ 的实际获赞总数，到账须通过 QQ 页面或独立查询确认。

## 使用与配置

仅需 Repository Secret：`QQ_CARD_CLAIM_TARGET`，值为目标 QQ 号。不要填写 QQ 密码、Cookie 或登录令牌。

- `inspect`：只读取公开商品页面。
- `eligibility`：提交目标号码进行价格预览，拦截下单接口。该模式仍会向第三方站点发送号码。
- `submit-once`：保留受控单次提交代码，**当前工作流不提供此选项**。必须同时具有显式提交开关、手动 workflow_dispatch 事件及首次运行条件；普通 push、重新运行以及当前只读工作流都无法提交。

工作流文件目前仅存在于此功能分支。GitHub 的手动运行入口通常要求工作流先注册在默认分支，因此本分支的 `workflow_dispatch` 声明不等于已提供可点击入口。后续若需要常规手动检查，应先将审核后的工作流注册到默认分支；本次未修改默认分支。

## 防重复与隐私

- 单次运行最多放行一个匹配目标号码的 POST 下单请求。
- 提交前必须取得明确的零元价格预览；未知值、布尔值和空字符串均不作为零元。
- 禁止重新运行已执行的提交任务；不自动重试、不切换代理、不轮换账号。
- 这些防护不是跨所有新运行的永久订单去重；当前不开放自动提交，以避免误用。
- 报告只保存预定义状态、HTTP 状态、布尔值、版本和时间，不保存 QQ 号、原始回包、页面正文、订单编号或登录数据。
- 独立报告保留 7 天，便于区分“未提交”“受理”“拒绝”和“结果未知”。

## 验证

所有语法检查及行为测试均在 GitHub Actions 执行，不在当前服务器执行。测试覆盖免费判定、预览与下单结果不一致、限额识别、目标精确匹配、单次放行、只读拦截、禁止重跑以及报告脱敏。

这些测试使用合成数据，不证明第三方站点当前有额度，也不会产生订单。
